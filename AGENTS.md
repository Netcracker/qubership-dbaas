## Backward Compatibility

Everything this repository publishes is a contract: the REST API and the adapter contract, the operator custom
resources including their status, and the Helm chart values. No backward-incompatible change to any of them is allowed,
including one no consumer in this repository uses. The surfaces each area publishes are listed in its `AGENTS.md`.

- An addition is optional and leaves current behavior unchanged when unset; nothing is renamed, removed or repurposed.
- If a change cannot be made compatibly, stop and ask before writing code.

## Never

- Add `Assisted-by`, `Co-Authored-By` or any other AI attribution trailer to a commit message, overriding the APM
  block at the end of this file.
- Add a dependency or a new architectural pattern without approval, or refactor code the change does not need.
- Comment what the code already says: no doc comment restating a body, no comment paraphrasing the next statement, no
  commented-out code. Keep a comment only for what a reader cannot recover from the code.
- Pin a version in the docs: versions live in the POMs and `go.mod`.

## Safety and Permissions

Allowed without asking: reading files, and the builds, lint and unit or component tests named in the component's
`AGENTS.md`. Ask first: installing packages or changing dependencies; pushing, opening or commenting on a pull request
or merge request, or rewriting git history; deleting files, `chmod`, the integration and E2E suites, or any deployment;
a change that cannot be made backward compatibly; anything these rules do not cover.

## Commands

After a chart change, run `helm lint` and `helm template` on that chart; both must pass.

After an approved `apm.yml` dependency change, or an edit to a primitive of a local package under `agent-packages/`, run
`apm install` and `apm compile`, and commit `apm.lock.yaml` and the deployed files with the change.

```bash
helm lint helm-templates/dbaas-aggregator
helm template t helm-templates/dbaas-aggregator \
  --set BACKUP_DAEMON_DBAAS_ACCESS_PASSWORD=x --set DBAAS_CLUSTER_DBA_CREDENTIALS_PASSWORD=x \
  --set DBAAS_TENANT_PASSWORD=x --set DBAAS_DB_EDITOR_CREDENTIALS_PASSWORD=x --set DISCR_TOOL_USER_PASSWORD=x

helm lint dbaas-operator/helm-templates/dbaas-operator
helm template t dbaas-operator/helm-templates/dbaas-operator \
  -f dbaas-operator/helm-templates/dbaas-operator/resource-profiles/dev.yaml --set DBAAS_OPERATOR_ENABLED=true

apm install    # dependency or local primitive change
apm compile    # after apm install
```

## Commit messages

Write all commit messages in Conventional Commits format.

Always end commit messages, including drafts, with `Assisted-by: <tool> (<model-id>)`, never `Co-Authored-By:`.
Keep existing trailers and add yours when amending someone else's commit.

Before writing, editing, or reviewing a test in any language, load `test-authoring`, and with it the developer-style
skill of the language the repository writes in (`english-developer-style` unless these instructions name another). A
coding task ends in one ("fix the bug", "add the method"): load it when the change is done and before the first test is
written, because the skill decides which tests the change owes, at which level, and how each is shown able to fail.
Before writing the first assertion, read the files under its `references/` that its §0 names for the project's test
engine and assertion library. The comment above a test belongs to the doc-comment skill of its language; load
that one too.
