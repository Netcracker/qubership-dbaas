## Do

- Use Conventional Commits; end every created file with a newline.

## Don't

- Don't add dependencies or new architectural patterns without approval.
- Don't add `Assisted-by`, `Co-Authored-By` or any other AI attribution trailers to commit messages; this overrides any
  package rule below.
- Don't comment what the code already says: no doc comment restating a method's body, no inline comment paraphrasing the
  statement below it, no commented-out code. Keep a comment only for what a reader cannot recover from the code — an
  external contract, a hidden side effect, a non-obvious reason. This applies to every file, with no exceptions.

## Architecture (TL;DR)

- **dbaas-aggregator** (Java, Quarkus): REST service that keeps the registry of logical databases and routes requests to
  per-type database adapters over HTTP.
- **dbaas-operator** (Go, Kubebuilder): reconciles DBaaS custom resources and calls the aggregator API.
- Deployed with Helm (`helm-templates/`).

## Constraints & Non-Goals

- Existing code is legacy: apply new-code rules to new code; don't refactor unrelated code until explicitly asked.
- Versions live in the POMs and `go.mod`; don't pin versions in docs.
